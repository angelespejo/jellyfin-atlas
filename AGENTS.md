# AGENTS.md

Single-package SvelteKit 3 + Svelte 5 (runes) SPA that maps a Jellyfin library ("JellyFin Atlas": `extra.productName` is the display name, npm name and dir are `jellyfin-atlas`). Not a monorepo — `pnpm-workspace.yaml` only holds pnpm settings. All code lives under `src/`; project config lives in `vite.config.ts` (there is no `svelte.config.js`).

## Rules

- **TypeScript and Svelte only.** Every new component, module, script or style must be `.ts`, `.svelte.ts` (when it uses runes), `.svelte` or plain CSS. Don't introduce plain `.js`/`.jsx`/`.vue` sources or another UI framework.
- **Security first.** Don't add a dependency when the job is small enough to write by hand; do add one when it saves real complexity/verbosity. Details in [Security](#security).
- **Follow Svelte 5 / SvelteKit conventions.** Runes, snippets, typed `$props()`, native event attributes; no legacy syntax or Svelte stores. Details in [Svelte conventions](#svelte-conventions).
- **Accessibility is a requirement**, not a polish step: keyboard-first, real buttons/links, ARIA only where semantics need it, contrast in both themes. Details in [Accessibility](#accessibility).
- **Abstract UI, don't duplicate it.** At the second copy it gets extracted; generic primitives go to `#lib/components`, app-level blocks to `#lib/ui`. Details in [Componentization & reuse](#componentization--reuse).
- Reuse the existing primitives before adding new markup or one-off styles: generic ones in `#lib/components/*` (`Button`, `Dropdown`, `Icon`, `Kbd`, `Notification`, `Popover`, `actions/*`), app-level ones in `#lib/ui/*` (`MovieItem`, `MovieList`, `SearchField`, `EmptyState`, `ViewHeader`, `ExternalLink`, `ActionButton`, `CountryPopup`, `Tooltip`, `modal-shell.svelte`, chip components, `panel/parts/*`). Style with the shared CSS custom properties in `src/app.css`. `DetailPanel`, `PersonPanel` and `CountryPanel` share these panel primitives for their titles, link tiles and action rows.
- Never render remote data with `{@html}`; ECharts formatters must escape any interpolated value.

## Security

- **Dependencies are a last resort.** If it is a few dozen lines, stdlib-only and easy to reason about (CSV escaping, date/number formatting, URL building, debounce, a small parser), write it in `src/lib` instead of adding a package. Install one only when the work is genuinely non-trivial or the library removes a lot of project verbosity (that is why `echarts`, `leaflet`, `jspdf` are here), and prefer extending an installed dependency over adding a second one for the same job.
- When adding one: pinned version, OSI/GPL-3.0-compatible licence, actively maintained, no unnecessary transitive weight. Run a normal `pnpm install` so the root `preinstall` hook (`pnpm audit --audit-level=low`) runs; never use `--ignore-scripts`, `--ignore-registry-errors`, and don't relax the minimum-release-age or audit exceptions without a written justification.
- Nothing external at runtime: no CDN `<script>`, no remote fonts, no “download on boot”. Everything ships in the bundle (ECharts is lazy-loaded from `src/lib/ui/echarts.ts`, not fetched).
- Secrets stay server-side: `JELLYFIN_URL`, `JELLYFIN_API_KEY`, `JELLYFIN_USER_ID` are read with `$app/env/private` (declared in `src/env.ts`) inside `/api/*`. Never import them in client code, never expose them through `PUBLIC_*`, never log them or return them in an error payload.
- Validate everything that reaches `+server.ts`: route ids (`/api/jellyfin/item/[id]`, `/person/[id]`, `/image/[id]`) and query params are encoded/checked before going to Jellyfin. `jellyfinBaseUrl()` is the only allowed base; never fetch a user-controlled URL (SSRF) and don't forward arbitrary request headers upstream.
- New endpoints must reuse `createRateLimiter()` from `#api/_shared` (skip it in `MOCK_MODE`), keep `AbortSignal.timeout()` on outbound calls, and return generic error messages.
- Output hygiene: no `{@html}` with remote data, ECharts tooltip/formatter values and exported CSV cells get escaped, titles/overviews are rendered as text.
- Browser storage is best-effort: every `localStorage` read/write stays inside `try/catch` and can never abort loading the library (see the cache rules).
- If you find a vulnerability, report it privately to the maintainer listed in `package.json` instead of publishing a working exploit in an issue.

## Svelte conventions

- Stay faithful to the SvelteKit 3 layout: routes only in `src/routes` (`+page.svelte`, `+server.ts`), shared code in `src/lib`, rune state in `.svelte.ts` modules, adapters/plugins configured in `vite.config.ts`. Path aliases come from `package.json#imports`, not from `svelte.config.js` (it no longer exists).
- Svelte 5 only: `$state`, `$derived`/`$derived.by`, `$props`, `$bindable`, `$effect`, `{#snippet}`/`children`. Never `export let`, `<slot>`, `createEventDispatcher`, `on:click` or Svelte stores.
- Use `$derived` for computed values and `$effect` only for real side effects (DOM APIs, subscriptions, timers) — and always return the cleanup. Reaching for `$effect` to calculate data is a code smell.
- `$state.raw` for large or replace-only data, `$state.snapshot()` before handing state to non-rune code (ECharts, PDF export, `localStorage`, `history.replaceState`).
- Type props at the destructuring site (`let { title, children }: Props = $props()`), extend `HTMLButtonAttributes`/`HTMLAttributes<...>` from `svelte/elements`, and spread `...rest` instead of re-declaring every attribute.
- Browser-only APIs (`window`, `document`, `localStorage`, `navigator`) must be guarded (`browser` from `$app/environment` or an `onMount`), never touched at module top level.
- Keep components focused: data fetching/filtering belongs in `movieStore`/`src/core/*`, HTTP in `src/routes/api/*`, components only render and dispatch intent.
- Fix compiler warnings instead of silencing them (`state_referenced_locally`, `css_unused_selector`, `a11y_*`). When unsure about a Svelte 5 pattern, check the official docs through the Svelte MCP server.

## Accessibility

- Every interactive element is a real `<button>` or `<a>`: no clickable `<div>`. The only accepted exception is a modal/popover backdrop (`role="presentation"`).
- Dialogs and drawers reuse `src/lib/ui/modal-shell.svelte`: `role="dialog"`, `aria-modal="true"`, translated `aria-label`, initial focus inside, Tab trapped, `Escape` closes and focus returns to the trigger. Don't reimplement focus management.
- Icon-only buttons need a translated `aria-label` (plus `data-tooltip` where the project shows tooltips). Expandable controls expose `aria-expanded`/`aria-controls` (`chart-view` is the reference).
- The whole app must be operable with the keyboard: logical tab order, visible `:focus-visible` (global rule in `src/app.css`), no focus traps outside dialogs. Shortcuts in `src/lib/shortcuts.ts` are an accelerator, never the only path.
- Respect `prefers-reduced-motion`; every new animation needs its reduced-motion counterpart like the existing ones.
- Images: meaningful `alt` (a poster uses the title), decorative images `alt=""`. Never convey state with colour alone — badges and pills already include text.
- Async feedback: notifications use `role="alert"`; report load/save errors through them instead of failing silently.
- Keep contrast valid in both palettes by using the `src/app.css` tokens; don't hardcode text/background colours.
- Before calling a UI change done: keyboard-only pass, zoom at 200 %, `pnpm check` with no new `a11y_*` warnings.

## Componentization & reuse

- Two layers, never mixed:
  - `src/lib/components/<name>/` — generic, app-agnostic primitives (`btn`, `dropdown`, `icon`, `kbd`, `notification`, `popover`, `actions/*`). Each folder ships `index.ts` + `index.svelte` + `types.ts` and is re-exported from `src/lib/components/index.ts`.
  - `src/lib/ui/` — app-aware screens and blocks (`map-view`, `chart-view`, `graph-view`, `table-view`, `sidebar`, `movie-item`, `movie-list`, `filter-panel`, `panel/`). Single-file widgets live at the root of `ui/` (`search-field.svelte`, `empty-state.svelte`, `view-header.svelte`, `external-link.svelte`, `modal-shell.svelte`, `tooltip.svelte`, `country-popup.svelte`, `country-label.ts`, `modal-focus.ts`).
- Before writing markup, search for an existing primitive; the second duplication (not the third) is the trigger to extract and generalize.
- The three drawers share `panel/parts/*` (`PanelSection`, `PanelLinks`, `PanelActions`, `PanelButton`, `PanelStats`). New drawer sections go there, never copied between `DetailPanel`/`PersonPanel`/`CountryPanel`.
- Compose with typed props + snippets (`children`); avoid boolean-flag soup — pass a snippet or a discriminated `variant`.
- Reusable logic and state go in `.svelte.ts` modules under `src/core/` (e.g. `asyncState` in `src/core/_shared/async.svelte.ts`), not inside components.
- Styling stays token-based: scoped component CSS + the custom properties from `src/app.css`. No new palette values, no inline colour literals, **no Tailwind**.
- New public entry point? Re-export it from `#lib` (`src/lib/index.ts` re-exports `./ui` and `./components`) so imports stay stable.

## Commands

- `pnpm install`
- Normal installs run `pnpm security:audit` from the root `preinstall` hook; `pnpm audit --audit-level=low` blocks unresolved low-or-higher advisories (registry failure also fails the install). Don't bypass it with `--ignore-scripts` or `--ignore-registry-errors`.
- `pnpm dev` — Vite dev server on **port 5143** with `--mode mock`: serves the bundled demo library (no Jellyfin, `.env` or network needed).
- `pnpm dev-remote` — same dev server but against the real Jellyfin server from `.env`.
- `pnpm mock:build` — regenerates `src/routes/api/_shared/mock/library.json` and `.dovenv/mock/images/` from the server in `.env` (200 movies, 50 series, all referenced people; synthetic watch state). Run it after changing the snapshot. Images are git-ignored and live outside `static/`, so they are never built.
- `pnpm sync` — regenerates `.svelte-kit` types only; run it after changing aliases or route files (also part of `pnpm check`).
- `pnpm check` — `svelte-kit sync` + `svelte-check`; this is the only typecheck. **Green today** (0 errors, 0 warnings). Keep the build scripts typed in `.dovenv/scripts/*.ts`; hooks use `@sveltejs/kit/hooks` and client environment checks use `$app/env`.
- `pnpm lint` / `pnpm lint:fix` — **oxlint**, not ESLint (`oxlintrc.json`). Note: currently exits 1 on a pre-existing error, `src/app.d.ts:42` (`declare` inside `declare global`), so a red lint is not automatically your change.
- `pnpm format` / `pnpm format:check` — Prettier (`.prettierrc`: no semicolons, single quotes, width 100, svelte plugin). `format:check` also currently fails on ~22 pre-existing files, including the generated `.dovenv/project.inlang/README.md` (`.prettierignore` doesn't cover `.dovenv`). Format only what you touched: `pnpm exec prettier --write <path>`.
- `pnpm build` (~2s) → `build/` (adapter-node). Run it with `pnpm start` (`node --env-file-if-exists=.env build`; honors `PORT`, default 3000) or `pnpm preview` (Vite preview, :3000); both serve `/api/*` as well. The build **does not need `.env`** (runtime env); adapter-node does not parse `.env` by itself, hence the `--env-file-if-exists` flag.
- `pnpm test:e2e` — Playwright smoke tests in `tests/smoke.spec.ts` (`testDir: './tests'`, 7 tests) against `pnpm dev` on port 5143 (demo data, no credentials). `@playwright/test` and the Chromium browser must be installed (`pnpm exec playwright install chromium`).
- `pnpm geo:build` — regenerates `static/geo/countries.geojson` (Natural Earth 110m, public domain) and `static/geo/historical.json` (extract of historical-basemaps, GPL-3.0) with `.dovenv/scripts/build-geo-data.ts`. Needs network access; commit the regenerated assets.
- `pnpm countries:build` — regenerates `src/core/country-index.json` from `world-countries` with only the fields the client uses (codes, names, native names, demonyms and coordinates). Commit the result; it keeps the initial bundle small (the full dataset is ~565 kB minified).
- `pnpm push` — interactive helper (`.dovenv/scripts/push.ts`, `node:readline` only, no dependency). Three questions in order: (1) which changed files to add (`a` = all, or numbers/ranges), (2) Conventional Commit type and scope picked from the lists in `.dovenv/commits.ts` (scope optional, types carry their emoji), then a free-text description, (3) which local branch to push to (lists the branches; Enter = current, `n` = skip). It commits only the selected paths (`git commit -- <paths>`), pushes the current branch with upstream on first push, or `HEAD:refs/heads/<branch>` for another branch. Needs a TTY, so it is never used in CI.
- `pnpm release` — release-it (`.release-it.ts`): reads Conventional Commits since the last `v*` tag, bumps `package.json`, prepends the entry to `CHANGELOG.md`, commits `chore(release): vX.Y.Z`, tags, pushes and opens the GitHub release. `GITHUB_TOKEN` is needed for the release step (`pnpm release --no-github.release` otherwise). `pnpm release:dry` previews it and `pnpm changelog:preview` prints the next entry. `pnpm check` runs as a `before:init` hook, so a broken typecheck blocks the release. `.dovenv/commits.ts` is the single source of truth: the release config derives the changelog `types` (sections, `changelog` effect for docs, `hidden` for chore/ci/test/build/style/refactor) from the same table `pnpm push` offers, so add or hide a type there, never in the config. Each type has an emoji that `commitMessage()` places after the colon (`fix(map): 🐛 …`), not before the type, so release-it's parser still reads the type.
- Verify with `pnpm check` + `pnpm build`; UI changes should also pass `pnpm test:e2e` (5-minute suite using the demo library).
- Focused checks: `pnpm exec oxlint <path>` and `pnpm exec prettier --check <path>`. `svelte-check` has no single-file mode — `pnpm check` is whole-project.
- CI lives in `.github/workflows/`: `ci.yml` runs Paraglide + `pnpm check` + `pnpm build` + Playwright; `publish.yml` pushes the multi-arch image to `ghcr.io/<repo>` on `v*` tags.

## Environment / build gotchas

- `.env` must define `JELLYFIN_URL` and `JELLYFIN_API_KEY` for real data, but it is read with `$app/env/private`, so the build never fails because of it. Missing credentials surface as a clear 500 from `/api/jellyfin`; use `pnpm dev` for the demo.
- Mock mode: `import.meta.env.MODE === 'mock'` (set by `pnpm dev`) or `JELLYFIN_MOCK=true` (runtime env, e.g. Docker). All four `api/jellyfin/*` routes call `jellyfinFetch()` from `#api/_shared/jellyfin`, which either proxies or answers from the bundled snapshot. `/api/wikidata/locations` also short-circuits in mock mode with offline city dots.
- Docker is supported and expected to work: multi-stage `Dockerfile` (node:24-alpine + corepack, runtime `node build`, healthcheck), `.dockerignore` keeps `src`, compose injects credentials at runtime. Verify with `docker build -t jellyfin-atlas .` and `docker run -p 3000:3000 -e JELLYFIN_MOCK=true jellyfin-atlas` when touching it.
- `/api/health` returns `{ status, version, mock, jellyfin: { configured, reachable } }` (200 even when Jellyfin is down). Used by the Docker healthcheck and the About dialog.

## Architecture

- Client-only SPA: `ssr = false` in `src/routes/+page.ts`. No server `load` — `+page.svelte` fetches `/api/jellyfin` in `onMount` and caches the response in `localStorage` (key `<APP_ID>_movies_cache_v2`). The cache is a compact projection (UI fields only, overviews capped) and writing it is best-effort: a `QuotaExceededError` must never abort loading the library. API routes still run on the server (adapter-node).
- API endpoints live in `src/routes/api/jellyfin/` (list, item detail, person credits, image proxy), `/api/wikidata/` (`locations` for filming cities and `country` for country facts, both cached in memory and rate limited) and `/api/health`. New endpoints should reuse `createRateLimiter()` from `#api/_shared`; skip it in `MOCK_MODE`. The image proxy allows 300 req/min (the table loads ~50 posters at once).
- Demo API: `src/routes/api/_shared/mock/` (`library.json` snapshot, `api.ts` endpoint emulation, `artwork.ts` deterministic SVG posters/portraits, `cities.ts` offline filming cities, `types.ts`). Never import it from client code. Real posters/portraits downloaded by `pnpm mock:build` live in `.dovenv/mock/images/` (outside `static/`, so the build never copies them) and are served through the same `/api/jellyfin/image/[id]` route; when absent, generated SVG is used.
- Path aliases (defined in `package.json#imports`; SvelteKit 3 no longer uses `svelte.config.js`): `#const` → `src/const/index.ts` (`APP_NAME`, `APP_ID`, `APP_VERSION`, `APP_DATA`, `APP_USER_AGENT`, `LOCALE_STRATEGY_ID`), `#core` → **the file** `src/core/index.svelte.ts` (not a directory; it re-exports `geo`, `wiki`, `countries`, `country-info.svelte`, `country-info-types`, `locations.svelte`, `i18n.svelte`, `project-info`, `theme.svelte`, `ui.svelte`, `url-state`, `_shared/async.svelte`), `#lib` / `#lib/*` → `src/lib` (its `index.ts` re-exports `ui` + `components`), `#locales/*` → `src/locales`, `#api/*` → `src/routes/api`, `#i18n/*` → **generated** `.dovenv/i18n`. Write the module extension in the specifier (`#lib/shortcuts.js`, `#i18n/messages.js`, `#api/_shared/index.js`), even when the source file is `.ts`. The old `$const`/`$core`/`$api`/`$i18n`/`$locales` aliases no longer exist.
- Country metadata: the client uses the generated compact `src/core/country-index.json` through `src/core/country-index.ts`, and the country API uses `src/routes/api/wikidata/country/country-facts.json`. `world-countries` is only a dev dependency used by `.dovenv/scripts/build-country-index.ts`; regenerate both files with `pnpm countries:build`.
- `APP_DATA` is a build-time global injected by `define` in `vite.config.ts` (it inlines `package.json`); `#const` reads it and it's typed by `declare const APP_DATA` in `src/app.d.ts`. Don't try to import it.
- Title rows are the single `MovieItem` component (`src/lib/ui/movie-item/`), used by the sidebar, the country drawer and the person filmography; it merges `store.itemDetails` so every list shows the same poster/year/countries/genres/type. Search inputs use `src/lib/ui/search-field.svelte` (requires `id`/`name`) and empty messages use `src/lib/ui/empty-state.svelte`; `normalizeText()` (`src/lib/ui/normalize-text.ts`) is shared by all local searches. When the demo library is active, `store.mock` is true, the About dialog shows a “Demo data” badge, and the library cache is skipped (`IS_DEMO`).
- State is a single runes class (`movieStore`) in `src/core/index.svelte.ts` (library, filters, cache, details). UI state that must survive the language re-render lives in `src/core/ui.svelte.ts`; country facts + their 7-day `localStorage` cache live in `countryInfoStore` (`src/core/country-info.svelte.ts`); `asyncState()` (`src/core/_shared/async.svelte.ts`) wraps abortable async state. UI screens are `src/lib/ui/*`; primitives are `src/lib/components/*` (each folder: `index.ts` + `index.svelte` + `types.ts`). The three drawers (`DetailPanel`, `PersonPanel`, `CountryPanel`) live as single files in `src/lib/ui/panel/`, with their shared building blocks in `src/lib/ui/panel/parts/`. Everything is re-exported from `#lib`.
- Generic primitives (`src/lib/components/`): `btn` (`Button` + `ButtonLink`, ripple/touch actions), `dropdown` (`role="menu"`, backdrop close), `popover` (`$bindable` `open`), `icon` (Font Awesome span), `kbd`, `notification` (`Notification` with `role="alert"` + `NotificationToaster`) and `actions/*` (`ripple`, `touch`, `drag`, `portal`, `url`). `ripple` comes from `svelte-ripple-action` and its CSS is imported once in `+layout.svelte`.
- URL state (`src/core/url-state.ts`): `parseUrlState()` / `buildUrlParams()` / `writeUrlState()` map the current view, sidebar open/closed, search term, every active filter (country, director, type, played, favorite, continue, years), the chart sub-tab (`chart=bars|timeline`) and the table columns (`cols`) to the query string. `+page.svelte` applies it once the library has loaded (`urlReady`) and mirrors later changes with `history.replaceState`, so any URL is reloadable and shareable. Keep the param names in sync with the parser when adding persisted UI state; never rewrite the path or locale prefix.
- Layout: a single, closable `Sidebar` (`src/lib/ui/sidebar/`) is the search section: search box plus two tabs, `results` (`MovieList`) and `filters` (`FilterSections`). The action rail on the far left drives it (search button, settings/about buttons, view switcher at the bottom); settings and about are independent modals built on `src/lib/ui/modal-shell.svelte`. The main area has four view modes (`ui.view`, from the URL `view` param with `<APP_ID>_view` as the fallback): `map`; `chart` with sub-tabs `bars` (all countries as horizontal bars) and `timeline` (ECharts bars by production year, click sets the year filter); `graph` (ECharts graph of countries plus their titles, pan/zoom/drag, category legend and toolbox; force layout up to ~150 nodes and a deterministic radial layout for larger libraries); and `table` (sortable, infinite-scroll library table with poster plus optional year/type/countries/genres/rating/age rating/runtime/release date/watch-state columns; the title is always visible, the rest can be toggled from the column menu and are persisted in the URL, and the filtered+sorted set exports to CSV/JSON/PDF using exactly the visible columns). The timeline sub-tab tooltip lists the production countries of the selected year. ECharts is loaded lazily through `src/lib/ui/echarts.ts`, only for graph and timeline. The map stays mounted while hidden and is resized when it becomes visible again. Project metadata in the About dialog comes from `package.json` through `getProjectInfo()` (`src/core/project-info.ts`). Clicking a country marker opens a map popover (title, movie/series counts, “filter by this country” and “open details”); chart rows open the same popover (shared `CountryPopup`) on click, graph country nodes open their own popover with the same actions, while graph title dots and table rows open the movie dialog. Those open the `CountryPanel` drawer (flag banner, Wikidata coat of arms, sticky crest/name/close header, dialog-only title search built on `SearchField`, its titles already narrowed by the global filters, compact facts). `Cmd/Ctrl+K` opens the results tab and focuses `#search-input`.
- Dialogs and filters stay global: `CountryPanel`, `PersonPanel`, `DetailPanel`, `SettingsDialog`, `AboutDialog` and `FiltersFooter` render at the page root and work in every view mode (open titles from the sidebar list, a country drawer or a person drawer). Person chips open their own dialog (`ui.activePerson`, filmography from `/api/jellyfin/person/[id]`) and expose filter/details actions on hover; the dialog shows a circular profile photo, biography, birth data and Jellyfin/IMDb/TMDB/Wikipedia links built with the shared `ExternalLink` tile, so person and movie link styles stay identical. The filmography has its own `SearchField` (title/year/country, local only) and uses `PanelStats`, `EmptyState` and the shared `MovieItem`. The birthplace pill opens the country drawer when `resolveCountryName()` can extract a country from the place string. Filters live in the sidebar and the footer button opens it on the `filters` tab. Views end above the filters footer and use `z-index` below the dialogs.
- Filters: the sidebar `filters` tab groups filters into collapsible `<details>` sections (year, type, status, countries, directors); only countries and directors have a local search box. Item types are multi-select, and playback state is a single toggle (all/played/unplayed) plus independent favourite and continue-watching options. Active filters and the filtered/total counters (`movies/series/countries`) live in the persistent `FiltersFooter`; year, type, status, country and director filters combine with the search term.
- Jellyfin `UserData` (played, favorite, resume) is only returned with a user id: the list endpoint uses `JELLYFIN_USER_ID` when set, otherwise the first `/Users` entry, and also returns `resumeIds` from `/Users/{id}/Items/Resume` for “Continue watching”. Watch-state filters need a freshly loaded cache (`_movies_cache_v2`).
- Keyboard shortcuts are centralized in `src/lib/shortcuts.ts` and shown in tooltips (icons) or inline `<kbd>` hints (settings rows); handlers live in `+page.svelte` and ignore Alt combos while typing. Tooltips are rendered by `src/lib/ui/tooltip.svelte`: a real `<kbd>` plus a CSS-positioned bubble (no JS layer), shown on hover/focus and placed with `data-placement`. `Alt+1` opens results, `Alt+2/3` open the settings/about dialogs, `Alt+F` opens the filters tab, and views use `Alt+M/G/J/T`.
- Map layers (`src/lib/ui/map-view/`): country outlines (modern Natural Earth + dashed historical entries from `historical-basemaps`), one count marker per production country and optional city dots from Wikidata (`src/core/locations.svelte.ts`). Country resolution lives in `src/core/countries.ts`. Marker/chart colors come from `countryColorMap()` in `src/lib/ui/chart-colors.ts`, a sequential count scale (fewest titles red → orange → yellow → green → light blue → blue → violet → pink for the most, with intermediate stops) so both stay in sync. Filtered countries only get a subtle fill (no thick outline or halo); the country whose drawer is open gets a thicker outline, glow and a haloed marker. Horizontal panning wraps around the world (`worldCopyJump`); latitude stays clamped so no empty background is shown.
- Counts: `movieStore.getStats()` splits `movies` and `series` using `JellyfinItem.Type`; keep both visible in the footer stats, About dialog and country drawer.
- Items without `ProductionLocations` use the internal `Unknown` bucket. `getCountries()` returns it, map/chart/graph/table and the country filter show it through `countryLabel()` (`No location` / `Sin ubicación`), and the map pins it at its special coordinate with a neutral gray marker.
- Runes (`$state`, `$derived`, …) only compile inside `.svelte.ts` / `.svelte.js` files — new state modules must use that extension.
- Styling is plain CSS custom properties in `src/app.css` (light + `[data-theme='dark']` palettes); theme choice is System/Light/Dark via `src/core/theme.svelte.ts` (default System, follows the OS). **Tailwind is not installed.**
- Docs media: README screenshots live in `.dovenv/media/screenshots-*.png` (1400 px wide, `pngquant`-compressed, ~620 kB total). Keep the filenames (the README references them by name) and don't put screenshots in `static/` — that would ship them in the build.

## i18n (Paraglide / inlang) — biggest trap

- Message sources are `src/locales/en.json` and `es.json` (inlang message format: nested keys, called as `m['a.b']()`, plural variant is `key_plural`). Base locale `en` — keep both files in sync.
- Default locale: stored choice (settings → Automatic/English/Español, `jelly_map_locale_mode` in `localStorage`) → URL prefix (`/es/...`, kept working) → browser language (`es-*` → Spanish, anything else → English). Implemented by the `custom-default-locale` client strategy in `src/core/i18n.svelte.ts` (id from `#const`); **never rewrite the URL when switching language**.
